# Persistent parametric memory

On a supported text model, Studio can learn from an old exchange, save the updated adapter, and omit that exchange from subsequent model input after source-free recall checks pass. The full exchange remains in the saved chat archive. Later answers can draw on the loaded parameters with no lookup of the retired source text. A parameter update is lossy, and finite checks do not guarantee future perfect recall. Additional online workflows and memory scopes are described in the [online learning guide](test-time-learning.md).

## What happens to a chat

1. Studio counts the packed history and current prompt against the selected Context budget. An eligible backend starts awake consolidation at **80%** of that budget. It selects old, complete user/assistant exchanges and keeps the most recent complete exchange. System instructions, tool exchanges and unfinished turns stay in text.
2. The trainer makes three passes over the selected dialogue using bounded, overlapping causal-token windows. The one-token overlap supplies the preceding token for the next prediction. Both sides of an ordinary exchange contribute training targets, including a fact supplied by the user and acknowledged only briefly by the assistant.
3. The service scores source continuations, a held-out foundation example and a bounded sample of older learned examples. Acceptance requires finite scores, improvement in aggregate source loss and no source or retention loss increase greater than 0.10 nats per target token. Before an exchange can retire, separate generated checks must demonstrate exact reconstruction of every addressed passage plus source-grounded question answering from answer-blind cues. JSON-decoded reconstruction preserves Unicode and whitespace. Large turns use segmented learning and validation with a durable cursor instead of a fixed character/output ceiling. Older committed recall checks are sampled across the learned history and checked again.
4. The trainer checks finite, nonzero parameter change and stages the checkpoint. One atomic pointer change publishes the generation and any verified retirement receipt together. If parameter validation passes but complete recall is unproven, the parameter update may persist while **all selected turns remain active**. Only a verified receipt shrinks the active prompt. The service can consolidate another batch until the active prompt approaches **60%** of Context. If the remaining input still exceeds the physical window, generation reports the capacity error.

At the hard limit, a validation-rejected oldest group does not prevent trying later eligible complete exchanges. Studio visits those later exchanges once, keeps the rejected text and newest exchange active, and stops as soon as the request fits. Runtime or persistence failures still stop recovery. Archive traversal uses bounded pages and releases its database read before each learning attempt.

**Sleep** offers both the original **Verified episodes (original Sleep/EWC)** queue and **Current chat exchanges**. The queue works even with an empty chat: it selects verified, unconsolidated solutions in descending surprise order, trains their completions with configurable anchor replay and EWC, and acknowledges the rows only after the selected model and scope have a validated, durable checkpoint. The shared legacy queue does not record an originating model; the panel names the current destination instead of guessing that provenance. A model-, scope- and content-bound receipt recovers a commit interrupted before database acknowledgement without repeating training. Current-chat Sleep starts one batch of complete exchanges on the loaded backend, including recent exchanges when eligible, and can run below the awake watermark. It retires text only after the recall checks above.

**Learn** uses the shared transaction after source verification. Its existing attachment preview retains up to 16,000 characters for synthesis, verification and RSI; malformed files in a folder are reported while readable lessons continue. Direct document ingestion remains strict. **RSI** trains its self-generated revision. Its training row contains the revision and a generic instruction. The source question, expected answer and verification verdict stay out of that row. Cancellation or rejection before publication keeps the previous checkpoint current and the uncommitted exchanges available as input. ## Backend capabilities

| Loaded text runtime | How the candidate reaches inference | Conditions for committing an update |
| --- | --- | --- |
| Native MLX language models | LoRA updates compatible language projections on the loaded model. MLX model operations run on its owner thread. | Compatible adapter layout, finite gradients and drift, candidate scoring, and checked MLX checkpoint serialization. |
| Packed Bonsai 2 and Bonsai 2 CRACK on MLX | Fresh compatible hybrid checkpoints use terminal attention-query and MLP down-projection adapters. Existing head-only generations restore their original layout. | Native replay checks, valid packed dimensions and matching checkpoint tensors. The packed backbone stays frozen; unsupported layouts keep a validated head-only fallback. |
| Transformers controllers on CPU or CUDA | PEFT updates compatible language projections. The updated in-process model scores the candidate, and the PEFT checkpoint is bound to the selected base. | A causal language module, supported projection targets, compatible installed training dependencies and validated persistence. |
| GGUF with llama.cpp or supported Prism runtimes | A verified compatible Hugging Face parent receives the PEFT update. The bridge converts the adapter to GGUF, loads it into the selected inference runtime, and scores the deployed candidate. | Matching parent lineage and tokenizer evidence, training resources, converter, native adapter loading and completion scoring. Native speculative servers additionally need a verified adapter API. |
| BitNet with bitnet.cpp | Train the verified BF16 parent, merge the adapter, rebuild I2_S and score the rebuilt model after loading it. | Verified parent lineage, a working conversion/quantization toolchain and a scoreable served deployment. |
| Strata | Strata serves the complete active text context using its native context limit. | The current integration lacks a verified parameter-update and adapter-loading path. Awake and Sleep retain chat text on this runtime. |

Each loader checks training capability for the selected model and device. The native bridges verify the deployed result because conversion and quantization can change what an adapter learned. Unsupported backends continue serving within their context limits. ### Existing training interfaces

The managed transaction runs alongside the standalone APIs. GGUF and BitNet `train(data)` still publish cumulative deployments at their original paths when no staging directory is supplied, including restoration of the previous deployment and optimizer state if publication fails. Explicit standalone training can resolve the selected remote parent when online; managed updates and capability checks require a local, verified parent. Non-MLX trainers retain completion-only supervision by default and accept explicit full-sequence supervision. Awake chat consolidation explicitly requests the complete exchange.

MLX `train_mini_batch(..., save_path=...)` preserves the caller's standalone export and writes its identity record alongside the managed generation. Existing managed generations are immutable. Matching partial Fisher/reference dictionaries remain accepted for EWC. Direct Torch/CUDA loading retains live public `model` and `tokenizer` handles through adapter wrapping, scope changes and unload; the load receipt and solve telemetry retain the requested runtime label. Internally, the shared controller owns placement and learning for those loads. ## Retention, storage and resume

EWC uses a diagonal Fisher estimate from foundation examples and penalizes movement of important adapter parameters relative to their pre-update values. Ordinary consolidation rehearses foundation and earlier continuations. A small recent replay pool and an indexed historical replay bank provide bounded rehearsal and held-out checks. Generated recall checks sample the oldest, newest and a rotating earlier receipt. They do not re-test every historical fact on every update. Rehearsal and validation use those records during learning. Ordinary generation receives the active transcript and the loaded weights.

Default model-wide generations reside under `learned_memory/<identity-digest>/` in the Studio data directory. Named scopes use separate identity/scope directories. The identity covers the selected base and adapter format, with verified source weights or revision and tokenizer/configuration evidence as available. The store keeps the current and preceding committed generations, plus document generations explicitly pinned by a memory catalog. Stage files can temporarily require more disk, especially while rebuilding a BitNet deployment. The adapter parameter count stays fixed for a given layout. Transcript text, replay records and retirement receipts grow on disk. SQLite indexes filter retired turn IDs before loading active text; archived history is prepared in pages before ordinary and media generation copy it. The GUI pages at most 100 transcript messages and bounds displayed text; long entries are previewed and the full archive can be exported. A single incoming string/SQLite row, model activations and unretired protected input still consume real memory. [State store](../core/learning_state.py) · [Transcript archive and retirement receipts](../core/context_memory.py) · [Display paging](../core/chat_paging.py)

An explicitly delimited `<document>…</document>` or `<context>…</context>` source can be learned in segments before generation while the actual question and surrounding instructions stay active. Arbitrary undelimited instructions, system/tool messages and unfinished exchanges are never discarded to force an input to fit. Failed reconstruction leaves the original source available and reports a capacity error if necessary.

Reopening Studio restores the text archive for its model tab and selected scope. Loading the matching checkpoint restores the corresponding active view. Memory Explorer shows the generation ID and opens the learning/scope controls. **Clear Chat** and **New Chat** clear that scope's transcript while preserving learned weights. API callers can use a distinct `ChatArchive(db_path, session_name)` for each resumable conversation. A caller that resubmits plain lists can give its consolidator a stable `session_id` to identify that session across processes.

When Studio discovers an older shared MLX adapter without a recorded base, it lists the file in **Memory Explorer**. Load its original base model, open Memory Explorer, choose **Import MLX adapter…** and select the raw `.safetensors` file. Studio reloads that base, validates and attaches the selected tensors, and preserves the source file. The next accepted learning update saves a model-bound generation. A shape match cannot establish which base produced an unlabelled adapter. [MLX checkpoint validation](../core/mlx_adapter_persistence.py) · [Memory Explorer](../app_gui.py)

Older GGUF/BitNet deployments and Transformers PEFT directories also remain usable. If loading reports an existing learned state without a model fingerprint, open **Memory Explorer** on its original base and choose **Restore learned state…**. Studio retries the original backend with that exact file or directory and reports success only after it is loaded. A changed model or named scope invalidates the pending selection. The old source remains unchanged; a later validated update creates the managed successor. Corrupt or incompatible state remains a load error, with no false import-success message. [Upgrade regression tests](../tests/unit/test_legacy_learning_migration.py)

The desktop Eval bridge keeps MLX learning in a directory specific to that evaluation run. Its mutable phase exports are separate from both desktop memory and immutable committed generations. Resuming an evaluation restores only that run's state. [Eval isolation tests](../tests/unit/test_app_eval_integration_contract.py)

## Continuing beyond the working window

Successfully learned and validated history can remain useful after its source leaves the active prompt, and checkpoints can restore that learned state across restarts. Best Work also projects archived history before constructing its passes. If an additional refinement cannot fit, it returns the preceding completed draft instead of hiding that answer.

This is not a guarantee that every request will fit. The current request, system instructions, tool results, recent turns and text whose recall is not yet verified still need working context. A single oversized protected input, failed learning, an unsupported backend or insufficient resources can prevent further generation. Studio retains the source and reports that limit rather than silently deleting it. Finite adapter capacity and subsequent updates also mean that persistent state does not guarantee perfect recall of every detail forever.

## Measure recall on Apple Silicon

Use a Mac with working MLX and the selected Bonsai 2 and CRACK snapshots. From the repository root, run the following command with the Studio Python environment active. Each run creates its own directory under the chosen output path and uses isolated model state.

```bash
python tools/evaluate_persistent_memory.py --model both --cycles 3 --output-dir ./eval_results/persistent_memory
```

For local snapshots outside the model cache, supply `--bonsai-path /path/to/bonsai` and `--crack-path /path/to/crack`. Downloads require `--allow-download`. The script writes `job.json`, per-stage records and `report.json`. It starts separate processes for baseline, update and reload measurements, asks for generated answers with empty source history, and retests earlier associations alongside unrelated controls.

By default, passing requires at least 75% final normalized exact-match fact accuracy, improvement over baseline, retention of previously correct facts, matching post-update and post-reload fact responses, and retention of initially correct controls. The implementation tests ran on Linux. The two 27B Apple Silicon runs are pending, so their recall rates and resource requirements under this evaluation remain unmeasured. [Fresh-process evaluation script](../tools/evaluate_persistent_memory.py)

## Research scope

TTT-E2E meta-trains models to learn from context through next-token updates. Titans trains a dedicated long-term neural memory module. Studio now combines periodic low-rank context consolidation with explicit query, evidence, few-shot, reward and document-memory workflows. The supported checkpoint retains its original architecture and finite attention window. Adapter capacity and the retention checks are finite, so longer chat histories carry no guarantee of perfect recall. Full architectures requiring offline preparation/meta-training are excluded from this implementation.
