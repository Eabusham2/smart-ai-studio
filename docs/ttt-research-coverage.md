# Which test-time training methods run in Studio?

Studio can update adapters on a loaded text model using documents, demonstrations, sampled answers, or a question’s context. Several papers below also change the architecture or train a model to learn its own update rule. Those components need compatible pretrained parameters or a separate training stage. The tables identify the online operation available for each paper and the parts outside this implementation. For runnable requests and backend setup, see the [test-time learning guide](test-time-learning.md).

## Online methods for existing checkpoints

| Research method | What runs in Studio | Scope of the implementation | Primary source |
| --- | --- | --- | --- |
| Original self-supervised TTT | `ingest` uses local text as supervision. `query_adapt` updates query adapters on context tokens before answering. | Transfers inference-time self-supervision to text. The original vision experiments jointly trained a classifier and an auxiliary self-supervised task before deployment. | [Sun et al., ICML](https://proceedings.mlr.press/v119/sun20b.html) |
| Query-only TTT (qTTT) | `query_adapt` prefills keys and values once, samples causal spans, and updates query-side LoRA factors. Packed hybrid decoders replay their terminal attention block against a frozen prefix. | Bounds follow the selected model and caller budget; the former 4,096-token ceiling is removed. Native bridges use the verified parent's cache. The source remains available during answering. | [Long-context qTTT, §3.1](https://arxiv.org/html/2512.13898v1) |
| Self-Guided TTT | `ingest` with `strategy=evidence` asks the model for spans relevant to a question. Only matching quotations within the selection budget become completion targets. | Operates on bounded chunks and skips empty selections. A verbatim span establishes where the text came from. Its relevance still depends on the selecting model. | [Self-Guided TTT](https://arxiv.org/abs/2607.09415) |
| Few-shot TTT | Leave-one-out examples, ordering augmentation, ARC geometry/color transformations, inverse-transformed voting and a separate unanswered query. | Uses existing model parameters with online adapters. The paper's prior fine-tuning remains excluded. | [Akyürek et al., ICML](https://proceedings.mlr.press/v267/akyurek25a.html) |
| TTT-Discover | Entropic advantages, PUCT, configurable schedules/expansion width, and frozen initial-policy KL with exact sampled token/logprob records on compatible Torch/MLX routes. | Local implementation; native text-only servers explicitly report missing reference scoring. Distributed rollouts and the authors' benchmark budget remain outside it. | [Learning to Discover at Test Time, §3.2 and Appendix A](https://arxiv.org/html/2601.16175v1) |
| Test-Time Reinforcement Learning (TTRL) | `reinforce` with `mode=consensus` derives rewards from agreement with a strict majority. Group-normalized rewards drive a clipped policy update over sampled completions. | Ties and uniform rewards give no update. A majority can endorse a wrong answer. The method reports agreement separately from external verification. | [TTRL](https://arxiv.org/abs/2504.16084) |
| TTT-Consolidate | Learns accepted individual and joint peer-conditioned trajectories, including supplied agents' messages, then generates a fresh answer. | Implements online trajectory consolidation and synthesis. The paper's offline meta-training is excluded. The best sampled trajectory and synthesis result are reported separately. | [Consolidating Reasoning with TTT](https://arxiv.org/abs/2611.02104) |
| InfiniteICL | `ingest` with `strategy=elicitation` generates source-grounded questions, checks whether the source-free model already answers them, and learns selected answer targets. Awake and sleep consolidation can retire validated dialogue exchanges. | Implements elicitation, selection and parameter updates. A dialogue receipt requires independent recall checks. The supported context and number of successful recalls remain finite. | [InfiniteICL](https://aclanthology.org/2025.findings-acl.595/) |
| Context distillation and adapter memory banks | Independent pinned document adapters, complete-source incremental indexing, model gating, source-free recall and multi-memory synthesis in ordinary chat or explicit bank answers. | Authenticated MLX hot activation with cold reload fallback. Bounded answer caching keys on the immutable generation. Different adapters never share an unverified KV cache. | [Context Distillation as Latent Memory Management](https://arxiv.org/abs/2605.28889) |
| Self-Adapting Language Models (SEAL) | Evidence selection and elicitation generate training targets online. Studio checks source grounding and commits validated updates. | Covers model-generated training data. SEAL also learns a policy for writing self-edits, including update directives, using downstream performance as an outer-loop reward. Studio supplies fixed workflows and explicit update budgets. | [SEAL](https://arxiv.org/abs/2506.10943) |

## Methods that require prepared architectures or learned update rules

| Research method | What the full method needs | Relationship to Studio | Primary source |
| --- | --- | --- | --- |
| TTT-Linear and TTT-MLP | A sequence layer whose recurrent state consists of parameters of a linear model or MLP. Its self-supervised updates are part of sequence processing. | Ordinary language models retain their original layers. Studio’s LoRA updates run at explicit learning boundaries. | [Learning to (Learn at Test Time)](https://arxiv.org/abs/2407.04620) |
| TTT-E2E | Sliding-window language modeling, online next-token updates and an initialization meta-learned through those updates. | The streamed causal objective is available through `ingest`. The trained initialization and end-to-end sliding-window model are outside the runtime. | [End-to-End TTT for Long Context](https://arxiv.org/abs/2512.23675) |
| Titans and MIRAS | Titans integrates neural long-term memory with attention. MIRAS describes architectures through their memory, objective, retention and learning rule. Their experimental backbones are trained with those mechanisms. | Studio couples the active transcript to learned parameters and can rehearse older material. Implementing either architecture requires a compatible model. | [Titans](https://arxiv.org/abs/2501.00663), [MIRAS](https://arxiv.org/abs/2504.13173) |
| In-Place Test-Time Context Distillation (IP-TTCD) | A long-window teacher supervises a short-window student’s hidden states. The in-place variant uses MLP parameters as fast weights and trains the model for that update. | Grounded answer targets can transfer information from a passage. Studio optimizes language-model outputs, leaving the paper’s hidden-state distillation and trained fast-weight path outside this release. | [Learning What to Remember](https://arxiv.org/abs/2608.01672) |
| TTT-NTP | A learned projection of the next contextual hidden state supplies a local write target for fast weights. The authors’ implementation trains and exports the required projection parameters. | Ordinary next-token cross-entropy runs in Studio. TTT-NTP’s hidden-state target and converted checkpoint architecture require their own integration. | [TTT-NTP](https://arxiv.org/abs/2606.21803), [authors’ training implementation](https://github.com/yancyou/TTT-NTP) |
| ParaTTT | A deep nonlinear recurrent memory and an iterative parallel algorithm for computing its inner-loop trajectory during training and prefill. | ParaTTT operates on a trained TTT sequence layer. Existing adapter trainers lack that recurrence and its kernels. | [ParaTTT](https://arxiv.org/abs/2610.38255) |
| Anchor | A sliding-window/recurrent hybrid with learned cross-layer read maps and writes at selected anchor layers. The paper evaluates trained or distilled variants. | Studio’s retention anchors are texts used in validation or Fisher estimation. Implementing Anchor requires the separate cross-layer recurrent state. | [Anchor](https://arxiv.org/abs/2611.04327) |
| Doc-to-LoRA | A hypernetwork trained to emit an adapter for an unseen document in one forward pass. | `bank_ingest` obtains document adapters by online optimization. The bank stores those adapters and indexes their provenance. One-pass generation requires learned hypernetwork weights. | [Doc-to-LoRA](https://arxiv.org/abs/2602.15902) |
| HOPE and Nested Learning | Nested Learning describes multiple optimization levels with distinct context flows. HOPE combines a learned self-modifying module with a continuum memory system. | Request, session, project and document scopes isolate ordinary checkpoints. Awake/sleep scheduling, replay and retention guards operate around the existing model. HOPE and its learned update rule require a separate architecture. | [Nested Learning](https://arxiv.org/abs/2512.24695) |

## What backend support establishes

- **Transformers and MLX-LM** can use adapter objectives when the loaded model exposes compatible trainable projections. Query-only learning additionally requires a supported split-query Llama, Mistral, Qwen2 or Qwen3 decoder and a compatible full-length cache in every layer. [Capability checks](../core/adaptation_capabilities.py) · [Query objective](../core/query_adaptation.py)
- **Packed MLX models, including supported Bonsai/CRACK runtimes,** use terminal query/down-projection adapters when their hybrid layout qualifies. Existing output-head checkpoints retain their old layout. **GGUF and BitNet** use verified parent objectives and a converter/rebuild route; the serving model validates the resulting deployment. **Strata 0.2.8 remains inference-only** because its integrated service exposes no verified adapter/update-and-scoring contract. [Backend matrix](test-time-learning.md) · [Native deployment](../core/native_context_learning.py)
- **Evidence of learning** comes from checkpoint and behavioral tests, including small real CPU model updates, cold restoration, and rejection of stale or corrupt generations. Published benchmark scores describe the authors’ systems. Studio accuracy, latency, and memory use on a production checkpoint require measurements on that checkpoint and its hardware. [Workflow tests](../tests/unit/test_online_learning_workflows.py) · [Scope and adapter tests](../tests/unit/test_scoped_memory_bank.py) · [Persistent memory evaluation](../tools/evaluate_persistent_memory.py)
